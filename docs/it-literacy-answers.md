# Webアプリケーション開発 ITリテラシー理解度チェック 回答

## 第1章 インターネットとネットワークの仕組み

### Q1. インターネットとは

インターネットとWebブラウザで見るホームページは同じものではありません。  
インターネットとは世界中のネットワークをつなぐものです。  
Webはインターネットをつないだ状態で提供されるサービスの１つです。  
道路がインターネットだとして車がいっぱい走っています。その車の１つにWebがあります。  

### Q2. IPアドレスとポート番号

localhostとは自分自身のパソコンを指します。  
その中でポート番号とは1台のパソコンで複数のプログラムが動くので、番号で見分けるために使われます。  
このプロジェクトでは5173はフロントエンド、8080はバックエンドなので  
localhost:5173＝自身のパソコンのこのプロジェクトのフロントエンド  
localhost:8080＝自身のパソコンのこのプロジェクトのバックエンド  
となります。  

### Q3. DNS

人間には覚えやすい名前が必要ですが、コンピューターは数字のIPアドレスで通信します。  
DNSは、名前をIPアドレスに変換する仕組みです。  
DNSはWebサイトの住所（IPアドレス）を調べてくれます。  
1. 名前を入力する
2. DNSで名前をIPアドレスに変換する
3. そのIPアドレスのサーバーに接続する
4. ページが表示される

という流れになります。  

### Q4. HTTPとは

HTTPとはハイパーテキスト・トランスファー・プロトコルの略です。  
トランスファー＝転送・移す  
プロトコル＝通信のルール  
ブラウザ「このページをみせてください」  
サーバー「はい、ページの情報を送ります」  
と、ブラウザとサーバーが会話するときのルールです。  

### Q5. HTTPとHTTPSの違い

HTTPSはHTTPに安全（Secure)の頭文字のSを加えて暗号化することです。  

現在WebサイトがほぼHTTPSなのはパスワードや個人情報を守るためです。  
HTTPのままだと、途中で誰かに情報を盗み見られたり、書き換えられたりされる可能性があります。  

### Q6. リクエストとレスポンス

リクエストは、クライアントからサーバーへのお願い  
レスポンスはサーバーからクライアントへの返事です。  
レストランで  
1. お客さんがお店に「ハンバーグください」＝リクエスト
2. 店員さんが注文されたハンバーグを持ってくる＝レスポンス

です。  

### Q7. HTTPメソッド

HTTPメソッドとはサーバーに「なにをしてほしいか」を伝えるための方法です。  

- GET：データを見る・取得する
- POST：新しいデータを追加する
- PUT：データ全体を更新する
- PATCH：データの一部を更新する
- DELETE：データを削除する

日常生活でメモ帳に例えると  

- GET：メモ帳を見る
- POST：新しいメモを書く
- PUT：メモを最初から書き直す
- PATCH：メモの一部だけ書き直す
- DELETE：メモ帳のそのページを捨てる

### Q8. HTTPステータスコード

- 200＝成功
- 201＝新規作成に成功
- 400＝リクエストが間違っている
- 404＝データが見つからない
- 500＝サーバー側でエラーが起きた

200、201は成功、400は送った内容に問題がある、404は探しているものがない、500はサーバー側に問題があると覚えるとわかりやすいです。  

### Q9. JSONとは

JSONとはデータを文字であらわすための書き方です。  
例: `{"title": "買い物", "done": false}`  
これは「タイトルは買い物」「まだ完了していない」というデータをあらわしたものです。  
人間でも読みやすい、データのやり取りがしやすい、様々なプログラミング言語で使えるという利点があります。  

### Q10. APIとは

APIは  
Application Programming Interface  
（アプリケーション・プログラミング・インターフェイス）  
の略です。  
プログラム同士が、決まった窓口を通して機能やデータをやり取りするといった  
アプリケーション同士をつなぐイメージです。  

直接データベースにアクセスしない理由は、大きく分けて安全面と機能面の２つあります。  

理由①：パスワードや大事な情報を盗まれたり、誰かに書き換えられるリスクがあるため  
理由②：データ処理や管理を、バックエンドにまとめて行える  

### Q11. CORSとは

CORSとはCross-Origin Resource Sharing  
（クロスオリジン　リソース　シェアリング）  
の略で日本語ではオリジン間リソース共有です。  

オリジン＝Webサイトの「出どころ」をあらわすもので  
オリジンは次の３つできまります。  

- プロトコル：HTTPやHTTPS
- ホスト名：localhostやgoogle.comなど
- ポート番号：5173や8080

例えば、  
http://localhost:5173  
http://localhost:8080  
この２つはポート番号が違うため別のオリジンとして扱われます。  
そのため、フロントエンドからバックエンドにアクセスするときに、CORSの設定が関係してきます。  

CORSは、ブラウザが別のオリジンへのアクセスを制限する仕組みに関係しています。これは、悪意のあるサイトから個人情報を盗まれたり、勝手にデータを操作されたりする危険を防ぐためです。  

そのため、バックエンド側でCORSの設定を行い  
http://localhost:5173 からのアクセスを許可することで  
フロントエンドからバックエンドへ安全にアクセスできるようにします。  

### Q12. クライアントとサーバー

クライアントとはサービスを利用する側（お願いする側）  
サーバーはサービスを提供する側（お願いに応える側）  
です。  

- ブラウザ＝クライアント（お願いする側）
- バックエンド＝サーバー（お願いに応える側）
- データベース＝サーバー（情報を保管する場所）

と考えられます。  
※バックエンドはブラウザから見るとサーバー、データベースから見るとクライアントになります。  

## 第2章 Webアプリケーションの構造

### Q13. フロントエンドとバックエンド

フロントエンドはユーザーに見える部分の画面表示でボタンなどの操作を担当しています。  
バックエンドとは裏側でデータの処理や、保存、ルールのチェックなどを担当しています。  
レストランで例えると、フロントエンドがホールで、バックエンドが厨房の役割を果たします。  
このアプリではフロントエンド（React）が画面表示やボタンの操作を担当し  
バックエンド（Spring Boot）が保存やデータの処理を担当しています。  

### Q14. 3層構造

３つの層は  
・フロントエンド（画面）  
・バックエンド（処理）  
・データベース（保存）  
に分かれています。  
理由①画面のデザインを変えても、データ処理は直さなくても良い  
理由②画面表示、データ処理、データ保存を別々に管理できる。  
理由③バックエンドの奥（データベース）で保管することにより、個人情報やパスワードなどの大事な情報を守れる  

### Q15. データの流れ

①ユーザーがフロントエンド（React）で「新しいタスク作成」ボタンを押す  
②フロントエンドがHTTPメソッドのPOSTを使って、タスクの情報をJSON形式でバックエンド（Spring Boot）に送る  
③バックエンドが受け取ったJSONの情報を確認してデータベースに保管する  
④データベースが情報を保存し、バックエンドに結果を返す  
⑤バックエンドがフロントエンドにHTTPステータスコード201（作成成功）と保存できたことを伝える  
⑥フロントエンドが返ってきた情報を使って、画面を更新して新しいタスク（カード）が画面の一覧に表示される  
という流れになります  

### Q16. エンドポイントとURL設計

1. {id}は、番号が入る場所です。
2. /api/tasks/5はその5番のタスクがある場所を指します
3. /api/tasksと/api/tasks/5の違いは、特定の１件と全体（一覧）の違いです

URLは「どこ(何に対して)」を表し、メソッドは「何をする」を表します。  

### Q17. 同期処理と非同期処理

同期処理とは１つのことが終わるまで、次の作業をせずに待つ方法です。  
非同期処理とは待っている間に、ほかの作業を進めるやり方です。  
同期処理はお弁当を温めている間待っていることで、非同期処理とはお弁当を温めている間洗い物をしている状態です。  

サーバーの待ち時間には次のようなことがあります。  
・インターネットを通してデータを送る時間がかかる  
・サーバーが受け取った情報を処理する時間がかかる  
・データベースに保存したり、処理する時間がかかる  

サーバーにお願いしてサーバーからの返信を待っている間も画面の操作をできるようにして、待ち時間でも画面が止まるのを防ぐためです。  

### Q18. SPA（シングルページアプリケーション）

従来のWebサイトは別のページに移動した時、全体を読み込み直します。  
一方SPAはページ全体を読み込み直さずに、ページの中の必要な情報だけを読み込み直して表示するアプリケーションです。  
タスクを追加した時に、ページ全体を読み込み直さずに、画面に新しいタスクのカードが追加されます。  

### Q19. 入力チェック（バリデーション）の多重防御

フロントエンドだけではチェックをすりぬけて、不正なデータが送信される可能性があるためです。  
バックエンドだけでは間違えている入力を送信する前に、画面に表示できず、使いにくくなる可能性があるためです。  
フロントエンドで入力ミスを防ぎ、バックエンドでも不正な情報を防ぎ、安全性と使いやすさを向上します。  

### Q20. エラーハンドリング

①エラーが起きたときは、「ネットワークに接続できません。」など何のエラーかわかるように表示させる。  
②「再試行」ボタンを表示して、もう一度APIを呼び出せるようにする。  
③エラーが起きても画面が正常に表示され、入力した情報が消えないようにする。  

## 第3章 データベースの基礎

### Q21. データベースとは

データベースとは、データを整理して、安全に、たくさん保存する仕組みです。  
ExcelやCSVとの違いは  
①大勢が同時に読み書きしても、データが破損しにくい。  
②データが増えても、探すのが速い。  
③権限の管理ができる。  
④壊れても復旧しやすい。  
データベースは大きな図書館です。大量の情報保存、検索、変更、削除ができます  

### Q22. テーブル・行・列

テーブル：データをまとめた表全体のこと。  
行（レコード）：タスク１件分のデータ。Excelの横１行のこと  
列（カラム）：番号、タスク名、状態、縦１列のこと  

tasksテーブル（例）  

| id | title | status |
|----|-------|--------|
| 1 | 買い物 | 未完了 |
| 2 | 掃除 | 完了 |

テーブル：この表全体  
行：１・買い物・未完了など、タスク１件分のデータ  
列：id、title、statusなどの項目  

### Q23. 主キー（PRIMARY KEY）

主キーとは他の行のデータが重ならないようにするための１つ１つの目印です。  
同じタスク名があっても番号で区別すればわかるようにするために必要です。  
変更や削除などを間違わないようにできます。  
同じ「買い物」というタスクがあっても「１」や「２」で区別できるようになります。  

### Q24. CRUD操作

CRUDとは、データを操作する、４つの基本動作です。  

- Create：POST　作成（新しいタスクを追加する）
- Read：GET　読み取り（タスク一覧や詳細を表示する）
- Update：PUT/PATCH　更新（タスクの名前や情報を変更する・別のリストへ移動する）
- Delete：DELETE　削除（不要になったタスクを削除する）

頭文字をとってCRUDです。  

### Q25. データの制約

`NOT NULL`：データを空欄にできないようにするための設定（必ず値を入力しなければいけない）  
`DEFAULT 'medium'`：値の指定がない場合、自動的に 'medium'になる設定  
例えば、優先度を選ばないでタスクを作成すると自動的に「'medium'」になります。  

目的  
- `NOT NULL`：必要なデータが空欄になるのを防ぎ、データを正しく管理するため。
- `DEFAULT 'medium'`：値が指定されなくても初期値を自動で設定し、入力の手間を減らすため。

### Q26. インデックス

インデックスとはデータを素早く検索できる仕組みです。  
本の索引と同じで、調べたい言葉が何ページにあるか、すぐに見つけられるようにするものです。  
索引がないと本の最初から最後までのページを１ページずつ探さないといけないため、時間がかかります。  
データベースにインデックスを設定すると大量の情報の中から調べたい言葉を素早く探せるようになります。  

### Q27. トランザクション

トランザクションとは複数の処理をひとまとめに扱い、全部成功したら確定、1つでも失敗したらなかったことにする仕組みです。  
タスクを別のカラムへ移動するとき、移動前の場所から削除する処理と、移動先に追加する処理を正しく行い、データの不整合を防ぐため、重要です。  
銀行でお金を振り込むとき、送り元（Aさん）からお金を引く処理と、送り先（Bさん）にお金を入れる処理があるとします。  
片方だけ成功するとお金が合わなくなるため、両方を正しく行うことが重要です。  

### Q28. SQLとORM

SQLとはデータベースに、保存、検索、削除、変更などをお願いをするための言語です。  
ORMとはプログラムのデータとデータベースのデータを結び付け、データの保存や検索、更新などを簡単に行えるようにすることです。  
プログラムの中で、たくさんSQLを書かなくてもデータベースのデータを扱いやすくするための仕組みです。  

## 第4章 開発プロセスとチーム開発

### Q29. バージョン管理（Git）

バージョン管理システムとはファイルの変更を記録し、誰が・いつ・何を変更したかを管理するシステムです。Gitはソースコードの管理に使われる代表的なバージョン管理システムです。  

必要な理由  
・過去の状態を確認したり、必要なら以前のバージョンに戻したりできる。  
・複数人で同じプロジェクトを同時に作業し、変更を統合できる。  
・変更の理由や内容を記録し、問題の原因を追いやすくなる。  
・ブランチを使って、本番の成果物に影響させず新機能や修正を試せる。  

使わない場合  
・古いファイルで新しい変更を上書きしたり、作業内容を失ったりする。  
・「最新版」「最終版2」など、どれが最新版かわからなくなる。  
・複数人の変更を手作業でまとめるため、変更の消失やミスが起きやすい。  

### Q30. ブランチとPull Request

ブランチとは、元のプログラムから枝分かれして、自分の作業を進めるための場所です。  

Pull Requestの目的は自分が変更したプログラムを確認してもらい、問題がなければmainに取り込んでもらうための仕組みです。  
他の人にコードを確認してもらったり、間違いを見つけてもらったりできます。  

全員がmainを直接変更すると、ほかの人の作業とぶつかったり、間違った変更によってプログラムが動かなくなったりする可能性があるからです。  
別のブランチで作業し、Pull Requestで確認してからmainに取り込むことで、安全に開発できます。  

### Q31. コミットメッセージの重要性

良いコミットメッセージを書くことで、どのような変更をしたのかが分かりやすくなります。  
後から内容を確認したり、問題が起きたときに原因を調べたりしやすくなるため、重要です。  
`feat: ログイン機能を追加` の feat は新しい機能を追加したことを表し、「ログイン機能を追加」で具体的な変更が分かります。  

### Q32. なぜ技術的な仕組みを理解すべきか

AIがコードを書いてくれていても、正しく動いているか確認したり、エラーが起きたときに原因を調べたりするためには、技術的な仕組みを理解する必要があると思います。ネットワークやデータベース、Webアプリケーションの仕組みを知ることで、AIに適切な指示がだせるようになったり、エラーの時の対処がAIと一緒にできるようになり、安全で使いやすいアプリを作れるようになると思います。  

この課題でフロントエンドとバックエンドの役割の違いを学んで、画面に表示する部分とデータを処理する部分が分かれていることが分かり、それぞれの仕組みを理解することが大切だと思いました。また、バックエンドとデータベースの仕組みを理解することで、データを安全に管理することにもつながると感じました。
